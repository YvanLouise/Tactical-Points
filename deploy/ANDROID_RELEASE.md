# 管理页更新安卓安装包

从原版游戏目录中的 `website/start-editor.cmd` 启动，在管理页顶部选择“安卓安装包”，点击“打包最新版并更新网站”。操作前会保存管理页的文案、图片与 README。

流程为：检查 GitHub 与本地环境 → 创建原版源码快照 → 加入安卓适配 → 构建并校验 APK → 上传新测试版本 → 更新官网的下载链接与版本文案 → 等待 Pages 部署成功。页面关闭后，本地服务中的任务仍会继续；重新打开面板可查看状态。

- 使用现有 `android_test/.build/keys/android-test.keystore`，包名保持不变，以支持覆盖升级；不会重新生成签名。
- 原版源码与旧安卓工程均不覆盖。快照和构建产物保存在 `android_test/.build/website-jobs/<任务编号>/`。
- 版本号根据源码版本和已发布安卓版本自动递增。新 APK、SHA256SUMS.txt 与 build-info.json 一同上传到独立 GitHub 测试版 Release；旧版本保留。
- 通过签名、包名和版本、启动入口、16 KB 对齐、真实 APK 内资源的无界面触摸导航验证后才上传。无界面验证不替代安卓设备性能测试。
- 校验或上传失败时不更新网站入口。已有通过校验的安装包可“重试上次发布”，不重复构建；GitHub Pages 失败时也可重试部署。
- 构建期间阻止其他窗口保存文案、图片或 README，并拒绝重复构建和并行网站发布；更新结束后管理页重新读取下载信息，保留本地未保存的其他字段。

需要 Windows、完整游戏工程、Godot 4.7 与安卓导出模板、Android SDK build-tools、JDK 17，以及当前账号对官网仓库的写入权限。默认沿用本机现有工具；可用 `GODOT_PATH`、`ANDROID_HOME`、`JAVA_HOME` 指定路径。此接口仅在本机服务中运行，沿用 Origin 与编辑凭据校验；公开 GitHub Pages 不提供打包接口。

状态与公开版本信息存于 `.cache/android-release-state.json`；GitHub 凭据仅从环境或系统凭据管理器读入内存，不写入日志和状态文件。管理页功能升级后，启动器会跳过旧协议的本地服务并选择可用端口。
